# 트래픽 대비 계획

> 2026-11-19 · 상태: **확정** (수치 가정은 12월 실측으로 보정)
> 2026-11-19 개정: 배포 인프라가 지인의 클라우드 네이티브 환경(수직·수평 확장 가능, MySQL)으로 정해져, GCP 이전은 **기본 계획에서 대체 계획(Plan B)으로** 내렸다.
> 관련: [인프라](infra.md), [일정](schedule.md), 정책 POL-OPS-06, 기능 F-OPS-08·09

## 왜 필요한가

비슷한 서비스 '내 트리를 꾸며줘'(2021)는 출시 5일 만에 가입 약 230만, 메시지 약 3,500만, **최대 동시 접속 약 117만**을 기록했다. 예상 서버비 10만 원이 약 2천만 원이 됐고 DoS 공격도 받았다 ([스브스뉴스 인터뷰](https://v.daum.net/v/VJ2CAHWQCL), [경향신문](https://www.khan.co.kr/article/202112231756011)).

배포 인프라는 확장이 가능하지만 **지인의 자원**이다. 그래서 12월 중순까지의 실측으로 12/24~25를 예측하고, 필요한 만큼 **미리 증설을 요청**한다. 지인 인프라를 쓸 수 없게 되는 경우에 대비해 GCP 대체 계획을 문서로 남긴다.

## 1. 측정 (12/1 ~ 12/15)

매일 한 번 기록한다 (F-OPS-08). 개인정보 없이 집계 수치만 남긴다.

| 지표 | 출처 | 쓰는 곳 |
|---|---|---|
| 누적·일별 트리 수 (T) | DB 집계 | 12/25 개봉 부하 예측 |
| 누적·일별 메시지 수 (M) | DB 집계 | 12/24 작성 부하, DB 용량 예측 |
| 시간대별 요청 수, 최대 RPS(초당 요청) | 배포 인프라의 지표 화면 또는 actuator `http.server.requests` | 피크 배율 계산 |
| p95 응답 시간, 5xx 비율 | 위와 같음 | 한계 접근 여부 |
| 인스턴스 수, CPU·메모리 | 배포 인프라의 지표 화면 | 확장 상태 |
| DB 크기, DB 연결 수 | MySQL 집계 쿼리 또는 배포 인프라 | DB 한계 |

배포 인프라에서 볼 수 있는 지표는 지인에게 확인한다 ([남은 질문](_open-questions.md) "배포 인프라").

## 2. 용량 측정 (출시 직후, 12/2 ~ 12/5)

실제 운영 환경에서 부하 테스트를 한 번 한다. **반드시 지인과 일정·범위를 맞춘 뒤** 진행한다 (자동 확장과 다른 서비스에 영향).

- 시나리오: 트리 보기(가장 많음) 70%, 메시지 작성 20%, 내 트리·메시지 열람 10%
- 결과: **C = 인스턴스 1대가 p95 응답 1초 이하, 5xx 1% 미만을 유지하는 최대 RPS**, 그리고 DB가 버티는 최대 RPS
- 도구: 저장소 의존성을 늘리지 않는 외부 도구(예: Docker로 실행하는 k6). 도입할 때 확인한다
- 실행 시간: 사용자가 적은 새벽. 테스트 데이터는 끝나면 지운다

## 3. 예측 (12/15)

12/1~15 실측값으로 아래 식을 채운다. **[가정]** 값은 실측 비율이 있으면 그것으로 바꾼다.

**12/24 (막판 작성)**
```
M_24 = 최근 7일 일평균 메시지 × α        [가정] α = 3 (전날 몰림)
RPS_24 = 최근 7일 최대 RPS × α
```

**12/25 00:00~01:00 (일괄 개봉)**
```
트리 수 T_25 = 현재 T + (최근 7일 일평균 신규 트리 × 남은 일수)
개봉 요청 수 = T_25 × p × r
RPS_25 = 개봉 요청 수 / 3600 × b
  [가정] p = 0.5  (첫 1시간 안에 여는 주인 비율)
  [가정] r = 20   (주인 1명의 요청 수: 내 트리, 메시지 페이지, 이미지 제외)
  [가정] b = 5    (1시간 평균 대비 0시 직후 몇 분의 순간 배율)
```

**필요 인스턴스 수**
```
N = ceil(max(RPS_24, RPS_25) / (C × 0.5))     2배 여유
```

**DB 크기**
```
DB 크기(1/31) = 현재 크기 + 일평균 증가 × 남은 일수
```

## 5. 대체 계획 (Plan B): GCP

평소에는 **실행하지 않는다.** 아래 조건이 생길 때만 꺼낸다.

| 단계 | 조건 | 옮길 것 |
|---|---|---|
| **B1** | 지인 인프라가 **MySQL을 제공하지 않음** | DB만 GCP **Cloud SQL for MySQL**. 앱은 지인 인프라 |
| **B2** | 11/26까지 배포 방식(빌드, 도메인, 비밀 값)이 정해지지 않음, 또는 운영 중 지인 인프라를 쓸 수 없게 됨 | 서버와 DB 모두 GCP |

### 구성

| 구성 | 선택 | 이유 |
|---|---|---|
| 리전 | `asia-northeast3` (서울) | 사용자와 가깝다 |
| 서버 (B2) | Compute Engine VM + Docker | 고정 외부 IP를 DuckDNS A 레코드에 넣을 수 있다. Cloud Run은 DuckDNS 연결에 로드밸런서가 필요하고 콜드 스타트 문제가 있다 |
| DB (B1·B2) | Cloud SQL for **MySQL 8.4** | 앱이 MySQL 기준이다 (8.0.16 이상) |
| 도메인 (B2) | **`pokeletter.duckdns.org`** | 이미 OAuth 3곳에 리다이렉트 URI로 등록되어 있다. A 레코드만 GCP IP로 바꾼다 |
| 계정 | PokeLetter 구글 계정 (`pokeletter.contact@gmail.com`) | 서비스 계정을 한곳에 모은다 |

### 크레딧

- 신규 계정 **$300, 가입일부터 90일**. 소진과 90일 중 먼저 오는 쪽에 끝나고, 멈추거나 연장할 수 없다 ([공식 문서](https://docs.cloud.google.com/free/docs/free-cloud-features))
- 체험이 끝나면 자원이 정지되고, 30일 안에 유료 전환하지 않으면 삭제된다. 우리는 1/31에 종료하므로 유료 전환하지 않는다
- **조건이 생기기 전에는 가입하지 않는다.** 가입한 날부터 90일이 줄어든다
- 예산 알림을 $100, $200, $270에 건다
- [확인 필요] 체험 계정의 동시 vCPU 상한 등 제한은 가입할 때 콘솔에서 확인한다

### 실행 절차 (조건이 생겼을 때)

1. GCP 가입, 프로젝트, 예산 알림
2. (B1·B2) Cloud SQL for MySQL 생성, 앱 DB 사용자에 DDL 권한. Flyway가 테이블을 만든다
3. (B2) VM에 Docker, 패치된 JDK 25 이미지로 앱 실행, 헬스 체크·로그인 확인
4. 데이터가 이미 있으면: 쓰기 중지(F-OPS-09) → `mysqldump` / 복원 → 행 수 비교
5. (B1) 지인 인프라의 `DB_URL`을 Cloud SQL로 바꿔 달라고 요청 / (B2) DuckDNS A 레코드를 VM IP로 변경
6. 쓰기 재개. 로그인 세션은 모두 다시 로그인해야 할 수 있다
7. 되돌리기용으로 이전 환경을 48시간 보존

**12/21부터는 이전하지 않는다.** 12/23부터 배포를 멈추는 원칙(D-06)과 같은 이유다.

### 지금 해 둘 보험 (비용 없음)

- DuckDNS 도메인 `pokeletter.duckdns.org`를 지우지 않고 유지한다
- OAuth 3곳(구글·카카오·네이버)의 DuckDNS 리다이렉트 URI를 지우지 않는다. 지인 도메인 URI는 **추가로** 등록한다
