# 포켓몬 IP 및 에셋 정책

> Source: Deep Interview, 2026-11-16

## Key Points (확정)

- **공식 포켓몬 리소스(스프라이트, 명칭)를 사용한다.**
  - 사용자가 위험을 인지하고 내린 결정이다. 권리자의 허가를 받은 사용이 아니며, 비상업적 운영이나 출처 표기로 허가가 생기지 않는다는 전제는 그대로 유지한다.
- **삭제 요청 대응: 에셋을 교체하고 운영을 유지하며, 메시지 내보내기를 제공한다.**
  - 문제가 된 리소스를 즉시 내리고 대체 에셋으로 전환한다.
  - 사용자의 트리와 메시지는 유지한다.
  - 종료가 필요해지면 사용자가 메시지를 보관할 수 있는 방법을 제공한다.
- **Public 저장소에는 직접 만든 에셋만 포함한다.** 포켓몬 이미지 파일은 저장소에 넣지 않는다.

## 이 결정에서 나오는 요구사항

| # | 요구사항 | 시점 (제안) |
|---|---|---|
| IP-1 | 캐릭터 데이터·이미지 URL을 "캐릭터 팩"으로 분리하고, 설정 하나로 팩을 바꿀 수 있게 한다 | MVP |
| IP-2 | **대체 캐릭터 팩**을 출시 시점에 준비한다. 1인 디자인이므로 최소 형태(예: 실루엣, 몬스터볼형 오너먼트, 번호만 있는 카드)로 만든다 | MVP |
| IP-3 | 모든 화면에 비공식 팬 프로젝트 고지와 상표권 귀속 문구를 표시한다 | MVP |
| IP-4 | 메시지 내보내기 기능 (형식은 나중에 결정: 텍스트, 이미지 등) | 출시 후 ~ 종료 전 |
| IP-5 | 연락 창구(이메일 등)를 공개해 권리자가 연락할 수 있게 한다 | MVP |
| IP-6 | 포켓몬 이미지를 저장소에 커밋하지 않는다 (`.gitignore`와 리뷰 규칙에 반영) | 즉시 |

## 아직 정하지 않은 것 (다음 단계에서 결정)

- **이미지 제공 방식:** 런타임에 외부 URL(PokéAPI 스프라이트 저장소 등)을 직접 불러올지, 별도 스토리지/CDN에 복사해 제공할지
  - 외부 URL 직접 사용: 비용 0, 저장소에 파일 없음. 대신 외부 서비스의 정책·가용성에 의존한다 (해당 서비스의 이용 정책은 확인 필요)
  - 자체 호스팅: 안정적이지만 이미지를 직접 배포하는 셈이 되고 트래픽 비용이 생긴다
  - → 인프라 단계에서 비용과 함께 결정
- **PokéAPI 데이터 사용 방식:** 런타임 호출 대신 빌드/시드 시점에 필요한 데이터(번호, 한국어 이름 등)만 받아 DB에 저장하는 방식을 제안한다. PokéAPI의 이용 정책(캐싱 요청 등)은 확인 후 반영한다
- **서비스 이름:** "포켓몬", "Pokémon" 등 상표가 이름에 들어가면 공식 서비스로 오인될 수 있어 위험을 키울 수 있다. 저장소 이름 `poke-letter`와 서비스 표기명을 따로 정할지 결정 필요
  - → **확정 (2026-11-16): Pokéletter (포케레터)**, ASCII 전용 환경에서는 `Pokeletter`. "Poké" 접두어가 공식 브랜드를 연상시킬 수 있다는 점은 위험 요소로 남겨 두며, 비공식 고지(POL-IP-01)를 반드시 함께 노출한다
- **포함 범위:** 몇 세대, 몇 종까지 쓸지 → MVP·게임 규칙 단계에서 결정
