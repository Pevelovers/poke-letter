# PRD — Pevelovers 크리스마스 롤링페이퍼

> 버전 0.1 · 2026-11-16 · 작성: Claude Code (기획 인터뷰 기반) · 상태: **초안 (검토 필요)**
> 근거 문서: [docs/planning/](../planning/_summary.md)
> 정책 가정 A-01~A-15와 서비스 이름은 2026-11-16에 확정했다.

## 1. 개요

친구들이 링크로 들어와 **포켓몬을 골라 메시지와 함께 선물**하면 내 크리스마스 트리에 장식이 달린다. 메시지 내용과 포켓몬은 **12월 25일에 한꺼번에 공개**된다.

- **서비스 이름:** **Pokéletter (포케레터)**. ASCII 문자만 쓸 수 있는 곳(도메인, 패키지명, OAuth 앱 이름 등)에서만 `Pokeletter`를 쓴다. 저장소 이름은 `poke-letter`
- **성격:** 비상업적 비공식 팬 프로젝트, 모바일 중심 웹
- **운영 기간:** 2026-12-01 출시 ~ 2027-01-31 종료

## 2. 목표와 비목표

### 목표
1. 12/1에 핵심 흐름(트리 생성 → 공유 → 메시지 → 12/25 개봉)이 모바일에서 끊김 없이 동작한다
2. 메시지가 적게 온 사용자도 서운하지 않다 (받은 포켓몬은 모두 "선물"이고, 채워야 할 빈칸이 없다)
3. 운영 비용 0원 신규 지출 (기존 EC2 + Supabase 무료 티어)
4. 삭제 요청을 받거나 시즌이 끝나도 사용자의 메시지를 지킨다 (에셋 교체, 내보내기)

### 비목표
- 수익화, 광고, 결제
- 도감 완성, 희귀도, 이로치, 업적 같은 게임성 강화
- 다중 트리, 계정 연동, 이메일 알림
- 시즌 이후 장기 운영

## 3. 사용자

| 사용자 | 설명 | 로그인 |
|---|---|---|
| **트리 주인** | 트리를 만들고 링크를 공유하고, 12/25에 메시지를 연다 | 필요 (카카오·구글·네이버) |
| **작성자** | 공유받은 링크로 들어와 메시지와 포켓몬을 보낸다 | 불필요 (닉네임만) |
| **방문자** | 링크로 트리를 구경한다. 작성자와 같은 화면을 본다 | 불필요 |
| **운영자** | 개발자 본인. 에셋 전환, 종료 공지, 데이터 삭제를 한다 | 서버 설정으로 처리 |

## 4. 핵심 시나리오

> 예외 흐름과 환경별 시나리오까지 포함한 상세본은 [유저 시나리오](user-scenarios.md)에 있다.

### S1. 트리 만들기 (트리 주인, 12/1~)
1. 랜딩 페이지에서 소셜 로그인
2. 트리 이름 입력 → 트리 생성
3. 공유 링크 복사 → 메신저로 친구에게 전송

### S2. 메시지 보내기 (작성자, 12/1~1/31)
1. 링크를 열면 트리와 장식(보낸 사람 닉네임)이 보인다
2. "메시지 남기기" → 닉네임, 메시지(500자 이하) 입력
3. 포켓몬을 검색해서 고르거나 "랜덤으로 보내기"를 체크
4. 전송 → 트리에 내 장식이 달린다. 랜덤이면 어떤 포켓몬인지 나도 모른다
- 작성 중 브라우저가 닫혀도 다시 열면 내용이 복구된다

### S3. 기다리기 (트리 주인, 12/1~12/24)
1. 내 트리에서 장식 개수와 보낸 사람 닉네임을 본다
2. 내용과 포켓몬은 잠겨 있다 ("12월 25일에 열려요")
3. 원치 않는 장식은 삭제할 수 있다

### S4. 개봉 (트리 주인, 12/25~)
1. 12/25 00:00(KST)부터 장식을 누르면 선물상자가 열리며 포켓몬과 메시지가 나온다
2. 받은 포켓몬 모아보기에서 선물받은 포켓몬을 한눈에 본다
3. 12/25 이후에 온 메시지는 도착하자마자 열 수 있다

### S5. 종료 (전체, ~1/31)
1. 1/17 이전에 사이트에 종료 공지가 뜬다
2. 트리 주인은 메시지를 내보내 보관한다
3. 1/31에 서비스를 종료하고 모든 데이터를 삭제한다

## 5. 화면 흐름

```
[랜딩 /] ──로그인──▶ [내 트리 /me]
                        │ 트리 없음 → [트리 만들기]
                        │ 트리 있음 → 공유 링크, 장식 목록, (12/25~) 개봉
                        ├──▶ [메시지 보기 /me/messages]   (12/25~)
                        └──▶ [받은 포켓몬 /me/collection] (12/25~)

[공유 링크 /t/:treeId] ──▶ [메시지 작성 시트] ──▶ [포켓몬 선택기] ──▶ 전송 완료
       (방문자·작성자)

[공통 하단] 비공식 팬 프로젝트 고지 · 개인정보 처리방침 /privacy · 연락처
```

화면별 기능은 [기능 정의서](features.md)에 있다.

## 7. 기술 구성

- FE: React 19 + Vite 8 + TanStack Router/Query + Tailwind/shadcn
- BE: Spring Boot 4.1 (Java 25) + Spring Security OAuth2 Client + JPA + Flyway
- DB: Supabase 무료 티어 PostgreSQL (서울, Session pooler)
- 배포: 기존 EC2(서울) 한 대에서 리버스 프록시가 FE 정적 파일과 `/api`를 함께 제공

## 8. 출시 기준 (12/1)

- [ ] S1~S3 시나리오가 iOS Safari, Android Chrome 실기기에서 동작한다
- [ ] 12/25 이전에는 API 응답 어디에도 메시지 내용과 포켓몬이 포함되지 않는다
- [ ] 욕설 필터가 닉네임, 메시지, 트리 이름에 적용된다
- [ ] 구글, 카카오 로그인이 운영 도메인에서 동작한다
- [ ] 비공식 고지, 개인정보 처리방침, 연락처가 모든 화면에서 접근 가능하다
- [ ] 대체 캐릭터 팩으로 전환하는 설정이 검증되어 있다
- [ ] 수동 백업 절차를 한 번 실행해 복구까지 확인했다
