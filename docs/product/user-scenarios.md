## US-01. 트리 만들기 (지우)

**전제:** 로그인하지 않은 상태

1. 지우가 `/`(랜딩)에 들어온다. 서비스 소개, 공개일(12/25), 로그인 버튼, 하단의 비공식 팬 프로젝트 고지가 보인다 (F-OPS-01)
2. "카카오로 시작하기"를 누른다 → 카카오 로그인 → 돌아와 `/me`로 이동한다 (F-ACC-02)
3. 트리가 없으므로 "트리 이름" 입력란이 보인다. "지우의 트리"를 입력하고 만든다 (F-TRE-01)
4. 트리가 만들어지고 공유 버튼이 강조된다

**결과:** 트리 1개, 장식 0개

| 예외 | 처리 |
|---|---|
| E1. 이름에 욕설이나 음담패설이 있음 | **트리를 만들 수 없다 (D-01 확정, POL-FLT-06).** 마스킹해서 저장하지 않고 `400 INAPPROPRIATE_NAME`으로 거절한다. 화면에는 "사용할 수 없는 표현이 있어요. 다른 이름을 입력해 주세요"를 보여 주고, 입력한 이름은 지우지 않아 바로 고칠 수 있게 한다. 어느 단어가 걸렸는지는 알려 주지 않는다 (우회 표기 시도를 돕지 않기 위해) |
| E2. 이름이 21자 이상 | 입력이 막힌다 (POL-TRE-02) |
| E3. 이미 트리가 있는 계정 | `/me`로 가면 기존 트리가 보인다. 두 번째 트리는 만들 수 없다 (POL-TRE-01) |
| E4. 로그인 도중 취소 | 랜딩으로 돌아오고 아무것도 만들어지지 않는다 |
| E5. 다른 제공자로 로그인 | 별도 계정이라 "트리 없음" 상태가 된다 (POL-ACC-04). 사용자가 헷갈릴 수 있어 `/me`에 "카카오로 로그인했어요"처럼 제공자를 표시한다 |

## US-02. 공유하기 (지우)

1. `/me`에서 "공유하기"를 누른다
2. 모바일에서는 기기의 공유 시트가 열린다(Web Share API). 지원하지 않으면 링크가 복사되고 "복사했어요" 안내가 뜬다 (F-TRE-02)
3. 지우가 단톡방에 링크를 붙여 넣는다
4. 카카오톡이 링크 미리보기를 보여 준다

| 예외 | 처리 |
|---|---|
| E1. 링크 미리보기 내용 | **트리마다 다르게 한다 (D-02 확정).** 예: 제목 "지우의 트리에 메시지를 남겨 주세요", 설명 "Pokéletter · 12월 25일에 열려요". 링크 미리보기 봇은 JavaScript를 실행하지 않으므로, `/t/:treeId` 요청에는 서버가 트리 이름을 넣은 Open Graph 메타 태그를 HTML에 채워 돌려줘야 한다 → 기능 F-TRE-08 |

## US-03. 메시지 보내기 (이슬)

**전제:** 단톡방 링크를 눌러 카카오톡 인앱 브라우저로 `/t/aB3dE5fG7h`에 들어옴

1. "지우의 트리"와 장식들(보낸 사람 닉네임)이 보인다. "12월 25일에 열려요 · D-23" 표시 (F-TRE-03)
2. "메시지 남기기"를 누르면 작성 시트가 올라온다 (F-MSG-01)
3. 닉네임 "이슬"과 메시지를 쓴다. 글자 수가 표시되고(F-MSG-03), 입력하는 동안 자동 저장된다 (F-MSG-02)
4. "포켓몬 고르기" → 선택기에서 "이브"를 검색해 이브이를 고른다 (F-CHR-01)
   - 또는 "랜덤으로 보내기"를 체크한다 (F-CHR-02)
5. "보내기" → 트리에 이슬의 장식이 달리는 모습이 나온다 (F-MSG-05)
   - 직접 골랐으면 "이브이와 함께 보냈어요", 랜덤이면 "랜덤 선물을 보냈어요"
6. 자동 저장된 내용이 지워진다

**결과:** 지우의 트리에 장식 +1. 이슬은 메시지를 다시 볼 수 없다 (POL-MSG-04)

| 예외 | 처리 |
|---|---|
| E1. 작성 중 앱이 닫힘 | 같은 링크를 다시 열면 쓰던 내용이 복구된다 (POL-MSG-05) |
| E2. 욕설 포함 | 전송은 되고 해당 단어만 `***`로 바뀐다 (POL-FLT-02). P1에서는 입력 중 미리 알려 준다 (F-MSG-04) |
| E3. 연달아 보냄 (1분 5회 초과) | `429` → "잠시 후 다시 보내 주세요 (N초)". 쓰던 내용은 남는다 (POL-ABU-01, POL-MSG-05) |
| E4. 트리가 가득 참 (200개) | **트리 화면에서 "메시지 남기기" 버튼을 숨기고 "이 트리는 장식이 가득 찼어요"를 표시한다 (D-03 확정).** 다른 사람이 동시에 보내 그사이 가득 찬 경우에는 보낼 때 `409 TREE_FULL` 안내가 나오고, 쓰던 내용은 남는다 (POL-ABU-03, POL-MSG-05) |
| E5. 네트워크 오류 | "전송하지 못했어요. 다시 시도해 주세요", 쓰던 내용은 남는다 |
| E6. 없는 트리 링크 (오타, 탈퇴한 트리) | "트리를 찾을 수 없어요" 화면 + "내 트리 만들기" 버튼 |
| E7. 포켓몬을 고르지 않고 보냄 | 보내기 버튼 비활성. "포켓몬을 고르거나 랜덤을 선택해 주세요" |
| E8. 지우가 자기 트리에 씀 | 막지 않는다. 작성자는 로그인하지 않아 구분할 수 없다 |

## US-03a. 보낸 뒤 내 트리 만들기 (웅이)

1. 웅이가 메시지를 보낸 뒤 전송 완료 화면에서 "나도 트리 만들기"를 누른다
2. US-01로 이어진다. 로그인 후 `/me`에서 트리를 만든다

- **전송 완료 화면에 "나도 트리 만들기" 버튼을 넣는다 (D-04 확정, F-MSG-10).** 이미 로그인해 있고 트리가 있으면 버튼 문구를 "내 트리 보기"로 바꾼다
- 인앱 브라우저에서 누르면 로그인 문제(ENV-01)를 만날 수 있다

## US-04. 기다리기 (지우, 12/1 ~ 12/24)

1. 지우가 `/me`에 들어온다. 로그인은 30일 유지되므로 다시 로그인하지 않아도 된다 (POL-ACC-03)
2. 장식 개수와 보낸 사람 닉네임이 보인다. 장식을 눌러도 "12월 25일에 열려요"만 나온다 (POL-RVL-01)
3. 장식이 10개를 넘으면 넘겨서 본다 (POL-TRE-04)

| 예외 | 처리 |
|---|---|
| E1. 로그인이 풀림 (재배포, 30일 경과, 다른 기기) | 랜딩에서 같은 제공자로 다시 로그인하면 트리가 그대로 있다 |
| E2. 지우가 공유 링크로 들어옴 | `isOwner = true`라 공유 화면에서도 "내 트리 관리" 버튼이 보인다 |
| E3. 12/25를 잊어버림 | 이메일을 받지 않아 알림을 보낼 수 없다. **리마인더는 넣지 않는다 (D-05 확정).** 친구들이 단톡방에서 개봉을 상기시켜 주는 흐름에 맡긴다 |

## US-05. 장식 삭제 (지우)

1. 지우가 `/me`에서 닉네임이 "로켓단"인 장식을 길게 누르거나 메뉴에서 "삭제"를 고른다
2. "삭제하면 되돌릴 수 없어요. 메시지 내용은 볼 수 없어요" 확인 → 삭제 (F-MSG-06, POL-MSG-06)

**결과:** 장식 -1. 공개 전이라 내용을 보지 않고 닉네임만으로 판단했다

## US-06. 개봉 (지우, 12/25 00:00 이후)

1. 지우가 `/me`에 들어오면 "메시지가 열렸어요!" 상태가 된다 (POL-RVL-02)
2. 장식을 누르면 선물상자가 열리며 포켓몬이 나오고, 메시지가 보인다 (F-MSG-07, F-MSG-08)
3. 다음 장식으로 넘기며 하나씩 연다. 목록에서 모아서 볼 수도 있다 (`/me/messages`)

| 예외 | 처리 |
|---|---|
| E1. 12/24 23:59에 화면을 켜 둠 | 남은 시간이 0이 되면 FE가 서버에 다시 묻는다. 서버 시각이 공개 시각을 지났을 때만 열린다 (POL-RVL-04) |
| E2. 개봉 연출이 아직 없음 (P1이 밀린 경우) | 연출 없이 메시지와 포켓몬을 바로 보여 준다 |
| E3. 포켓몬 이미지 로딩 실패 | 기본 오너먼트 이미지로 대신한다 (F-CHR-04) |
| E4. 00:00에 사용자가 몰림 | 기존 EC2 한 대에서 받는다. **문제가 생기면 운영자가 재시작하거나 직전 버전으로 되돌린다. 요청이 몰리면 로드밸런싱을 검토한다 (D-06 확정, POL-OPS-05)** |

## US-07. 받은 포켓몬 보기 (지우, 12/25 이후)

1. `/me/collection`에서 받은 포켓몬이 격자로 보인다 (F-CHR-03)
2. 같은 포켓몬은 하나로 묶이고 "×3"이 붙는다. 누르면 보낸 사람 닉네임이 나온다 (POL-CHR-05)
3. 전체 도감, 수집률, 빈칸은 없다

## US-08. 늦게 온 메시지 (지우, 12/26 ~ 1/31)

1. 12/27에 친구가 메시지를 보낸다 (US-03과 같음)
2. 지우는 `/me`에서 바로 열 수 있다 (POL-RVL-02)

## US-09. 내보내기와 종료 (지우, ~ 2027-01-31)

1. 1/17까지 모든 화면 상단에 "1월 31일에 서비스가 종료돼요" 배너가 뜬다 (F-OPS-03, POL-END-01)
2. 지우가 `/me/messages`에서 "메시지 내보내기"를 눌러 텍스트 파일을 받는다 (F-MSG-09)
3. 1/31에 서비스가 내려가고 데이터가 삭제된다. 이후 도메인에는 종료 안내 페이지만 남는다 (POL-END-03)

| 예외 | 처리 |
|---|---|
| E1. 종료 전에 한 번도 들어오지 않음 | 이메일이 없어 따로 알릴 방법이 없다. 메시지는 함께 삭제된다 |
| E2. 삭제 요청으로 대체 팩으로 전환됨 | 포켓몬 대신 오너먼트가 보이고 메시지 내용은 그대로다 (POL-IP-02) |

## US-10. 탈퇴 (지우)

1. `/me` → "탈퇴하기" → "트리와 받은 메시지가 모두 삭제돼요" 확인 (F-ACC-05)
2. 즉시 삭제되고 로그아웃된다 (POL-PRV-03). 공유 링크는 "트리를 찾을 수 없어요"가 된다 (US-03 E6)

## 공통 환경 시나리오

### ENV-01. 인앱 브라우저에서 로그인 (중요)

친구들은 대부분 카카오톡 링크를 눌러 **카카오톡 인앱 브라우저**로 들어온다. 작성자는 로그인하지 않으니 문제가 없다. 하지만 웅이(US-03a)처럼 인앱 브라우저에서 바로 트리를 만들려고 하면 로그인이 필요하다.

- **구글은 보안 정책상 인앱 브라우저(임베디드 웹뷰)에서 OAuth 로그인을 막는 것으로 알려져 있다** (`disallowed_useragent` 오류). 2026-11 기준으로 카카오톡 인앱 브라우저에서도 그런지는 실기기에서 확인해야 한다.
- 카카오 로그인은 카카오톡 인앱 브라우저에서 동작할 것으로 보이지만, 이것도 실기기 확인이 필요하다.
- [결정 필요 D-07] 인앱 브라우저로 감지되면 (a) 구글 버튼을 숨기고 카카오만 보여 줄지, (b) "기본 브라우저로 열기" 안내를 띄울지, (c) 둘 다 할지

### ENV-02. 로컬스토리지를 쓸 수 없음

일부 시크릿 모드나 저장소가 차단된 환경. 자동 저장이 조용히 꺼지고 작성은 그대로 할 수 있다 (POL-MSG-05).

### ENV-03. 화면 크기

모바일 세로 화면(폭 360px 안팎)을 기준으로 설계하고, 데스크톱에서는 가운데 정렬된 모바일 폭으로 보여 준다. [가정 아님, 제안]
